Capsule ToolboxPRE-RELEASE · WINDOWS

What it is. A Windows companion built on one rule: you can read it, you decide, it cannot do more than it says. It includes a privacy-hardened web browser, a 3D voxel home world, a studio for building 3D scenes, a forge that inspects game-mod packages without ever running them, and plain-language performance advice. An optional Linux layer runs approved AI models on your own machine — tested with real inference. The AI agents can only propose; a human approves; nothing runs free-form.

Why it exists. Most Windows tools ask for blind trust. The Toolbox shows every change as a named, described item before you approve it — and its own status page labels every feature Working, Prototype, or Not verified.

Capsule EcologyPRE-RELEASE · WINDOWS

What it is. The Toolbox grown into a native Windows application — one real program, no web shell. System tweaks bound by written rules, with a restore point demanded before the first change. Curated app packs installed for you through winget and Chocolatey (Microsoft's app installer and the community package manager) — starting with Add Back Edge, which restores the browser other tools delete. Repairs use Microsoft's own DISM/SFC sequence, with a restore-point manager and before/after snapshots of your system. And AI models you adopt like living things: downloaded from their original source, every file hash-checked, then copied and changed freely — with the family tree kept.

Why it exists. Everyone else sells optimization. Capsule sells verifiability — not "trust me," but "inspect it." Every change is a proposal; every result is a receipt in a hash-chained ledger you can verify.

VERIFICATION
The code compiles with 0 errors · its tweak list matches the shipped CapsuleOS 0.2.2 playbook exactly — 619 changes, 618 with an undo · its receipt ledger matches the SI Core's format exactly: test records pass, tampered histories fail · model files are verified the same way their source verifies them. One simple law: an agent proposes a change, using a permission it was actually given, and the result is written into a permanent record. Nothing acts without leaving a receipt. NimbusisA REAL OS · x86_64

What it is. A real operating system, built from the PoeTchi kernel work: it boots on standard PC hardware architecture (x86_64), runs programs in protected rings, and stores files on disk. Its agents are ordinary user programs holding permission tokens — never part of the kernel itself. The name is his coinage: nimbus + nemesis, "nimble nemesis," carrying the Raijin storm theme.

Why it exists. The kernels before it were theses. This one is the OS itself — the SI Core's constitution (people authorize; software never does) enforced by the machine, with every state change leaving a receipt.

PROOF
Boot test battery 36 of 36, run twice · a note file written to disk survives a reboot word-for-word · the file service can be killed and restarted and the file still reads back · programs run from disk. Written in Zig at the lowest level, with a documented path for Rust and C++ programs on top.
